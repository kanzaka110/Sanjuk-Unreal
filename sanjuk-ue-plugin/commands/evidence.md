# /evidence — 증거 패킷 정리 (GCP 메모리용)

이번 UE/SB2 작업을 다음 추론에 재사용 가능한 **증거 패킷**으로 정리한다.
git/P4 제출이 아니고, 전체 동기화(`/push`)도 아니다. **분석 기록만 남긴다.**

## 이 커맨드가 강제하는 3가지

1. **원인 후보 3개** — 패킷에 최소 3개 후보 섹션이 없으면 미완성으로 간주.
2. **폐기된 가설 + 폐기 이유** — 각 후보의 판정(채택/폐기)과 폐기 근거(관찰·로그·소스) 필수.
3. **단일 변수 변경 검수** — 수정이 한 번에 파라미터 하나였는지, 아니면 분리했는지 명시.

## 출력 형식 (그대로 채운다)

```
# [이슈명]
날짜: YYYY-MM-DD
작업 위치: (회사 PC / GCP)
대상 에셋: /Game/...

## 증상
- 조건:
- 보이는 문제:
- 빈도:

## 재현 조건
1.
2.

## 관찰된 사실 (추측과 분리)

- Chooser 결과:

- 발 배치 / 다리 IK / Control Rig 순서:
- Root Motion / Notify / Slot:
```

## 출력 범위 (중요)

- 이 커맨드는 **Evidence Packet Markdown 출력만** 한다.
- 파일 저장 안 함. MEMORY.md 인덱스 수정 안 함. GCP 동기화 안 함.
- 저장/동기화는 **사용자가 검토 후** 기존 `/push` 또는 별도 승인된 절차로 직접 한다.

## Hermes 교차검증 핸드오프 (비자명 원인 분석 시 기본)

패킷 출력 뒤, Hermes(비동기 반박·검수자)에게 전달할 **압축 검증 요청 블록**을 이어서 출력한다. 사용자가 Telegram 으로 전달 → Hermes 반박 → 로컬이 실측 검증 후 반영. 역할 정의: 메모리 [[reference-hermes-reviewer-role]].

```
> **[Hermes 검증 요청]**
> 이슈: [한 줄]
> 실측 (Monolith): [핵심 값/노드/Chooser 결과만]
> 내 후보+판정: A 채택(근거) / B 기각(왜 틀림) / C 기각(왜 틀림)
> 확인 못 한 것: [실측 불가했던 항목]
> 요청: 위 결론 반박해줘. 메모리 충돌 / 빠진 후보 / 단일변수 위반 있으면 지적.
```

원칙:
- **Hermes 응답은 ground truth 아님** — 지적사항은 로컬이 **실측으로 재확인 후** 채택/기각.
- 자명한(후보 1개로 확정) 이슈는 핸드오프 생략 가능.
- 블록은 회사 코드/토큰 대량 덤프 없이 **판단 근거 값만** 압축.

## 저장 (Hermes 학습용, 선택)

기본은 **출력만**(저장 안 함). 단 재사용 가치 있는 원인분석이면 사용자 판단으로 **보존**:
- `evidence/YYYY-MM-DD-<slug>.md` 로 저장 → `/push`(git) → GCP repo → `export-for-hermes.sh` #12 → `hermes-export/ue_evidence_packets.txt` → Hermes 학습.
- Hermes가 **우리 실제 추론 패턴(후보+반증+폐기이유)**을 학습해 검수가 날카로워짐.
- 저장은 **사용자가 명시할 때만**. 자동 저장 안 함. 상세: `evidence/README.md`.

## 보안·요약 원칙

- 회사 코드 / 토큰 / 비공개 원문을 **대량 덤프하지 않는다.**
- 에셋 경로 / 파라미터(전→후) / 노드 / 검증 결과 중심으로 요약한다.
- 로그는 원문 통째 붙이지 말고 판단 근거가 된 라인만 발췌.

## 미완성 거부 조건
- 원인 후보 < 3개
- 폐기 가설에 근거 없음 ("그냥 아닌 듯")
- 단일 변수 변경 여부 미기재
→ 위 중 하나라도 있으면 "패킷 미완성, 채워야 할 항목" 을 먼저 보고.
